문제 해결

안 될 때 — 증상별 해결법

실제 수업에서 자주 나왔던 사례를 이번 수업 기준(폴더 cheonan, 계정 userNN, 서버 별명 cheonan)으로 옮긴 것입니다. 명령의 userNN·<서버 IP>·30NN은 배정 시트의 본인 값으로 바꿔 넣으세요.

일치하는 항목이 없습니다. 다른 단어로 검색해 보시거나, 아래 스스로 해결하는 법을 참고하세요.
Windows에서 접속·인증이 계속 실패합니다 (반복적으로 인증이 안 될 때)
증상: Permission denied (publickey) / 계속 자격 증명을 다시 묻거나 연결이 끊김

가장 흔한 원인은 키 파일 권한 설정이 제대로 적용되지 않은 것입니다. 한 번 명령을 실행했더라도 경로 오타, 일반 권한 PowerShell, 부분 적용 등으로 권한이 어중간하게 망가진 상태로 남아 있을 수 있습니다.

핵심 — 먼저 /reset 으로 초기화한 뒤 다시 잠그세요같은 명령을 또 실행해 봐야 이미 꼬인 권한 위에 덧칠하는 셈이라 잘 안 고쳐집니다. icacls ... /reset 으로 권한을 기본 상태(상위 폴더에서 상속받는 원래 상태)로 되돌린 다음, 상속 제거 → 읽기 권한 부여를 처음부터 다시 하는 것이 확실합니다.

해결 순서 — 이 네 줄을 위에서 아래로

PowerShell을 반드시 관리자 권한으로 다시 열고, 아래를 한 줄씩 실행합니다. (경로·파일명은 본인 것으로)

PowerShell (관리자) — 권한 리셋 후 재설정
# 0. 파일이 그 자리에 있는지부터 확인 (True 가 나와야 함)
Test-Path "C:\cheonan\userNN.key"
# 1. 권한을 기본 상태로 초기화 — 꼬인 설정을 싹 지웁니다
icacls "C:\cheonan\userNN.key" /reset
# 2. 상속된 권한 제거
icacls "C:\cheonan\userNN.key" /inheritance:r
# 3. 나에게만 읽기 권한 부여
icacls "C:\cheonan\userNN.key" /grant:r "$($env:USERNAME):(R)"
# 4. 최종 확인 — 내 계정만 (R) 로 나와야 정상
icacls "C:\cheonan\userNN.key"
각 명령이 하는 일 /reset — 이 파일에 직접 붙어 있던 권한 설정을 전부 지우고, 상위 폴더에서 상속받는 기본 상태로 되돌립니다. 백지에서 다시 시작하는 단계입니다.
/inheritance:r — 그 상속된 권한마저 떼어냅니다. 이걸 해야 "Users 그룹 전체가 읽을 수 있음"이 사라집니다.
/grant:r "계정:(R)" — 이제 텅 빈 상태에 나에게만 읽기(R) 권한을 붙입니다.
즉 지우고(reset) → 상속 끊고(inheritance:r) → 나만 추가(grant:r) 순서입니다. 1번을 건너뛰면 이미 꼬인 설정 위에 덧칠하는 셈이라 같은 오류가 반복됩니다.

마지막 4번 결과에 내 계정 하나만 보이면 성공입니다. BUILTIN\Users, Everyone, Authenticated Users, NT AUTHORITY\... 같은 항목이 남아 있다면 아직 덜 된 것이니 1~3번을 다시 실행하세요.

그래도 안 되면 체크 • 파일 확장자 숨김 — 실제 파일명이 userNN.key.txt일 수 있습니다. 탐색기 보기 › 파일 확장명을 켜서 확인하세요.
• 경로 오타 — config의 IdentityFile 경로와 실제 파일 위치가 정확히 같은지.
• User 번호 — 다른 사람 번호를 적어 두지 않았는지.
• OneDrive 동기화 폴더(바탕화면·문서)에 키를 두면 권한이 되돌아가는 경우가 있습니다. C:\cheonan 같은 동기화되지 않는 폴더로 옮기세요.

바꾼 뒤에는 VS Code에서 Ctrl+Shift+P → Remote-SSH: Kill VS Code Server on Host 를 한 번 실행하고 다시 접속하면 깨끗하게 재시도됩니다.

"정말 연결하시겠습니까?" / "이 제공자를 신뢰합니까?"에서 더 진행이 안 됩니다
증상: 질문이 뜬 뒤로 아무 반응이 없음 / 버튼을 눌렀는데도 안 넘어감

이 질문은 두 가지 형태로 나옵니다. 형태에 따라 대응이 다릅니다.

① 버튼 형태 (Continue / Cancel)

그냥 Continue를 클릭하면 됩니다.

② 입력창 형태 — 여기서 많이 막혔습니다

화면 위쪽에 입력창이 뜨고 이런 문구가 나옵니다:

입력창에 나오는 문구 예시
Are you sure you want to continue connecting (yes/no/[fingerprint])?

여기서는 클릭할 버튼이 없습니다. 입력창에 yes를 직접 타이핑하고 Enter를 쳐야 넘어갑니다.

  • y 만 입력 → 안 됩니다. yes 세 글자를 전부 쳐야 합니다.
  • 빈 칸에서 그냥 Enter → 안 됩니다.
  • "이 폴더의 작성자를 신뢰하시겠습니까?", "Do you trust the authors…" 도 같은 방식입니다.
핵심 원칙서버 연결 과정에서 화면에 무언가 나타나면 반드시 읽고, 요구하는 대로 응답하세요. 대화형 절차라 여러분의 응답을 기다리는 중이지, 멈춘 게 아닙니다.
비밀번호를 물어봅니다 (password:)
증상: 접속 중에 userNN@<서버 IP>'s password: 처럼 비밀번호 입력창이 뜸

우리는 키 파일로 로그인하므로 비밀번호를 입력할 일이 없습니다. 비밀번호를 묻는다는 것은 키 파일이 제대로 쓰이지 않고 있다는 신호입니다. 입력하지 말고 Esc로 취소한 뒤 아래를 확인하세요.

  1. config의 IdentityFile 경로와 파일명이 실제 키 파일과 정확히 같은지 (Windows 경로는 / 슬래시로, .txt가 붙어 있지 않은지)
  2. config의 User가 배정받은 내 번호인지
  3. 키 파일 권한이 잠겨 있는지 — Windows는 위 첫 항목의 네 줄, Mac은 chmod 600
gh auth login 이 진행되지 않습니다 / 브라우저가 안 열립니다
증상: 코드는 나왔는데 그 뒤로 아무 일도 안 일어남

화면을 다시 보세요. 아마 이 문장에서 멈춰 있을 겁니다:

터미널
! First copy your one-time code: 1E52-6D02
Press Enter to open github.com in your browser...

Press Enter = Enter를 누르라는 지시입니다. 8자리 코드를 먼저 복사한 다음 Enter를 치세요.

Enter를 쳐도 브라우저가 안 열린다면

정상입니다 — 서버에는 브라우저가 없습니다. 내 노트북 브라우저에서 직접 열면 됩니다.

  1. 내 노트북 브라우저에서 github.com/login/device 접속
  2. 터미널에 표시된 8자리 코드 입력 (대소문자·하이픈 그대로)
  3. Authorize 승인 → "Congratulations, you're all set!"
  4. 터미널로 돌아와 ✓ Logged in as ... 확인
코드 만료코드는 몇 분 뒤 만료됩니다. 시간이 지났다면 Ctrl+C로 취소하고 gh auth login을 처음부터 다시 실행해 새 코드를 받으세요.
이미 로그인되어 있다면또 로그인하려 하면 "You're already logged into github.com. Do you want to re-authenticate?"가 뜹니다. 상태만 확인하고 싶다면 gh auth status를 쓰세요.
UNPROTECTED PRIVATE KEY FILE / Permissions are too open 오류
증상: WARNING: UNPROTECTED PRIVATE KEY FILE! / Permissions 0644 for 'userNN.key' are too open.

키 파일이 "아무나 읽을 수 있는 상태"라 SSH가 사용을 거부한 것입니다. 권한을 잠그면 해결됩니다.

Mac · 터미널
chmod 600 ~/cheonan/userNN.key
ls -l ~/cheonan/userNN.key   # -rw------- 로 나오면 성공
Windows · PowerShell (관리자)
icacls "C:\cheonan\userNN.key" /reset
icacls "C:\cheonan\userNN.key" /inheritance:r
icacls "C:\cheonan\userNN.key" /grant:r "$($env:USERNAME):(R)"

자세한 내용은 강의자료의 "키 파일 권한 잠그기" 장을 다시 보세요. 공식 안내: Remote Development Tips and Tricks — Fixing SSH file permission errors

Could not establish connection to ... — 연결 자체가 안 됩니다
증상: 연결 시도 후 실패 팝업 / Connecting to SSH host... 에서 멈춤

순서대로 확인하세요

  1. OUTPUT 패널을 보세요. 아래 패널 → OUTPUT 탭 → 오른쪽 드롭다운에서 Remote - SSH 선택. 진짜 원인이 여기 영어로 적혀 있습니다. 그 내용을 복사해 Claude에게 붙여넣으면 대부분 바로 진단됩니다.
  2. config 내용 확인 — HostName(배정 시트의 내 서버 주소), User(내 번호), IdentityFile(경로) 오타 여부. 서버가 두 대이니 옆 사람과 주소가 다를 수 있습니다.
  3. 인터넷 연결 확인 — 회사·학교·카페 와이파이가 SSH(22번 포트)를 막는 경우가 있습니다. 휴대폰 핫스팟으로 바꿔서 시도해 보면 원인 판별이 됩니다.
  4. 플랫폼 선택 오류 — 처음에 Linux 대신 Windows/macOS를 골랐다면: Ctrl+Shift+P → Remote-SSH: Settings에서 확인하거나, Remote-SSH: Kill VS Code Server on Host 후 재접속.
  5. 서버 쪽 문제 — 위를 다 확인했는데도 안 되면 강사에게 알려 주세요. 서버가 잠시 재시작 중일 수 있습니다.
Host key verification failed / REMOTE HOST IDENTIFICATION HAS CHANGED
증상: 접속하던 서버인데 갑자기 무섭게 생긴 경고가 뜸

서버가 재설치·재시작되어 지문(fingerprint)이 바뀌면 나옵니다. 내 컴퓨터에 저장된 옛 기록을 지우고 다시 접속하면 됩니다.

Windows · PowerShell / Mac · 터미널 (내 노트북에서)
ssh-keygen -R <서버 IP>

그 후 VS Code에서 다시 접속하면 fingerprint 확인 질문이 나오고, yes 또는 Continue로 진행하면 됩니다.

다른 방법~/.ssh/known_hosts 파일을 열어 해당 IP가 들어간 줄을 지워도 됩니다.
터미널에서 Ctrl+V 가 안 됩니다
증상: 복사한 명령을 터미널에 붙여넣을 수 없음

터미널에서는 Ctrl+C / Ctrl+V가 다른 의미(중단 / 특수문자)로 쓰입니다.

  • Windows: Ctrl + Shift + V 또는 마우스 오른쪽 클릭
  • Mac: Cmd + V (그대로 됩니다)
복사 버튼이 가이드의 모든 명령 상자에는 오른쪽 위에 복사 버튼이 있습니다. 눌러서 복사한 뒤 붙여넣으세요.
Port is already in use / EADDRINUSE
증상: npm run dev 실행 시 포트가 이미 사용 중이라는 오류

여러 사람이 한 서버를 함께 쓰기 때문에 포트가 겹치면 납니다. 또는 내가 아까 켠 것이 아직 안 꺼져 있는 경우도 많습니다.

  1. 먼저 이전에 실행한 터미널이 남아 있는지 확인 → 그 터미널에서 Ctrl+C로 종료
  2. 그래도 안 되면 내가 지정받은 포트 번호(30NN)가 맞는지 확인 — npm run dev -- --port 30NN
  3. 내 포트에서 돌고 있는 것을 강제로 정리:
서버 터미널
# 내 포트를 쓰고 있는 프로세스 확인
lsof -i :30NN
# 내가 띄운 개발 서버 정리 (내 계정 것만 종료됩니다)
pkill -u $USER -f "npm run dev"
주의다른 사람에게 배정된 포트는 쓰지 마세요. 상대방 작업이 끊깁니다.
npm install 이 실패하거나 npm: command not found
증상: 설치 도중 빨간 ERR! 메시지가 뜨고 중단됨
  1. 위치 확인 — pwd로 프로젝트 폴더 안에 있는지, ls로 package.json이 보이는지 확인하세요. 홈 폴더에서 실행하면 실패합니다.
  2. 노란색 npm warn / deprecated / vulnerabilities 는 오류가 아닙니다. 마지막에 added ○○ packages가 나오면 성공한 것입니다.
  3. 진짜 오류(npm ERR!)라면 그 메시지 전체를 복사해 Claude에게 붙여넣으세요. "이 오류가 왜 났고 어떻게 고치면 되는지 설명해줘"가 가장 빠른 길입니다.
  4. npm: command not found 가 나오면 내 노트북 터미널에서 실행한 것일 수 있습니다. 왼쪽 아래 파란 SSH 표시를 확인하세요.
막혔을 때 초기화 (프로젝트 폴더 안에서)
rm -rf node_modules package-lock.json
npm install
확장을 설치했는데 서버에서 동작하지 않습니다
증상: Claude Code 아이콘이 안 보임 / 확장이 회색으로 비활성

확장은 내 노트북용과 서버용이 따로 관리됩니다. 서버에 접속한 상태에서 확장 화면을 열고, 해당 확장에 "Install in SSH: cheonan" 버튼이 남아 있다면 아직 서버에 설치되지 않은 것입니다. 그 버튼을 누르세요.

설치 후에는 Ctrl+Shift+P → Developer: Reload Window 로 창을 한 번 새로고침하면 확실히 적용됩니다. 그래도 아이콘이 안 보이면 Ctrl+Esc(Mac: Cmd+Esc)로 Claude 패널을 열 수 있습니다.

접속이 너무 느리거나 "Setting up SSH Host…"에서 오래 멈춰 있습니다
증상: 첫 연결에 시간이 오래 걸림

첫 접속은 원래 느립니다. VS Code가 서버 쪽에 자기 부품(VS Code Server)을 설치하는 중이며, 여러 명이 동시에 접속하면 더 걸립니다. 2~3분까지는 기다려 보세요.

그 이상 걸리거나 실패를 반복하면:

  1. Ctrl+Shift+P → Remote-SSH: Kill VS Code Server on Host 실행
  2. VS Code 완전히 종료 후 재실행 → 다시 접속
사용자명이 한글이거나 경로에 띄어쓰기가 있어요
증상: 경로 관련 오류가 계속 나거나 명령이 이상하게 잘림

이래서 처음부터 C:\cheonan 같은 영문·공백 없는 경로에 키를 두라고 안내했습니다. 이미 다른 곳에 뒀다면 그 폴더로 옮기고 권한 설정을 다시 하세요.

프로젝트 폴더 이름도 마찬가지입니다 — 영문 소문자 + 하이픈(예: ax-board)을 권장합니다. 한글·공백·괄호가 들어가면 명령마다 따옴표를 붙여야 해서 사고가 잦습니다.

git push 가 거부됩니다 (rejected) / 충돌이 났습니다
증상: Updates were rejected because the remote contains work that you do not have locally.
