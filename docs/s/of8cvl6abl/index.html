내용 중에 node_modules와 .env 두 줄이 보이면 통과. No such file이 나오거나 두 줄이 없으면, Claude 패널에 “이 프로젝트에 맞는 .gitignore 만들어줘. node_modules와 .env는 꼭 제외해줘”라고 요청합니다.

.env가 왜 제외 목록에 들어가나요?

비밀값이라 금고에 올리지 않는 것이 원칙입니다. 대신 PART 4에서 따로 챙깁니다. 지금 “올려야 안전한 것 아닌가?”라고 느끼셔도 여기서는 제외가 맞습니다.

네 줄 실행 — 위에서 아래로 한 줄씩

서버 터미널 · 프로젝트 폴더 안에서 · my-shop은 본인 프로젝트명으로

마지막 줄이 끝나면 ✓ Created repository 내계정/my-shop on GitHub 와 ✓ Pushed commits to https://github.com/... 두 줄이 보입니다.

PART 2 · GitHub에 올리기 · 확인

③ 정말 올라갔는지 — 브라우저에서 눈으로 확인

“push 했으니 됐겠지”가 백업에서 가장 위험한 말입니다. 서버가 닫힌 뒤에는 다시 확인할 방법이 없으니 지금 3가지를 봅니다.

1. 최근 커밋 시간

저장소 첫 화면 파일 목록 위에 “○분 전”이라고 표시됩니다. 방금 올렸다면 몇 분 전이어야 합니다. “3주 전”이면 push가 안 된 것입니다.

2. 파일이 실제로 있는지

파일 목록에 package.json, src 폴더 등이 보이는지. 폴더를 클릭해 최근에 고친 파일을 열어 내용이 최신인지 한 번만 봅니다.

3. .env가 없는지

목록에 .env가 보이면 안 됩니다. 보인다면 비밀값이 올라간 것이니 문제 해결 → “.env가 GitHub에 올라갔다”를 바로 따르세요.

여기까지 되면

코드는 안전합니다. 서버가 사라져도 git clone 한 번으로 어디서든 되살릴 수 있습니다. 다음은 보험(ZIP)과 비밀값(.env)입니다.

PART 3 · 노트북으로 받기 · 1단계

① 폴더를 ZIP 한 개로 묶습니다

파일을 하나씩 받으면 수백 개를 옮겨야 하고, 폴더째 받으면 node_modules 때문에 한참 걸리고 중간에 멈추기도 합니다. 서버에서 먼저 ZIP으로 묶고, 그 파일 하나만 받는 것이 가장 빠르고 확실합니다.

ls -d */

PART 1에서 메모한 목록입니다. 이 중 챙길 폴더 이름을 다음 명령에 적습니다.

ZIP 만들기 — 부품 창고는 빼고

user99는 본인 계정 번호로, my-shop test 자리에는 챙길 폴더 이름을 띄어쓰기로 나열합니다. 폴더가 하나면 하나만 적습니다.

서버 터미널 · 홈 폴더에서
zip -r backup_user99.zip my-shop test \
  -x "*/node_modules/*" "*/.next/*" "*/dist/*" "*/build/*" "*/.cache/*"

글자가 우수수 지나가고 마지막에 프롬프트($)가 돌아오면 완료입니다.

이 명령이 하는 일

-r — 폴더 안까지 전부 담기 (숨김 파일 .env·.gitignore·.git도 포함됩니다).
-x "..." — 그 뒤에 적은 경로는 빼고 담기. node_modules, 빌드 결과물, 캐시를 제외합니다. 이것들은 새 환경에서 npm install·실행으로 다시 생깁니다.

zip: command not found가 나오면

서버에 zip이 설치되지 않은 경우입니다. 같은 일을 하는 tar 명령이 문제 해결에 있습니다 — 결과 파일 확장자만 .tar.gz로 달라집니다.

크기 확인 — 상식적인 크기인지

서버 터미널
ls -lh backup_user99.zip
출력 예시
-rw-rw-r-- 1 user99 user99 2.3M Sep 22 14:05 backup_user99.zip

웹 프로젝트 한두 개면 보통 수백 KB ~ 수십 MB입니다. 수백 MB 이상이면 node_modules가 들어간 것이니 -x 부분 오타를 확인하고 다시 만드세요. 반대로 0이나 수 KB면 폴더 이름을 잘못 적은 것입니다.

내용물 목록을 훑어보고 싶으면:

서버 터미널 · 처음 30줄만
unzip -l backup_user99.zip | head -30

PART 4 · 비밀값

.env — GitHub에 없는 유일한 것, 따로 챙깁니다

4강에서 Supabase 주소와 키를 .env에 적었습니다. 이 파일은 일부러 GitHub에 올리지 않기 때문에, ZIP 외에 한 곳 더 적어 두면 안심입니다.

왜 GitHub에 안 올라가나

.gitignore에 .env가 들어 있어서입니다. 키가 공개되면 누구나 내 데이터베이스에 접근할 수 있으므로, 코드와 비밀값을 분리하는 것이 원칙입니다. 그래서 새 환경에 코드를 clone하면 .env는 빈 자리이고, 직접 다시 넣어야 실행됩니다.

어디에 적어 두나

  • 비밀번호 관리 앱(1Password, Bitwarden, iCloud 키체인 등)의 보안 메모
  • 또는 본인만 보는 메모 앱의 잠금 메모

서버에서 내용 보기

서버 터미널 · 프로젝트 폴더 안에서
cd ~/my-shop
cat .env
출력 예시 (값은 본인 것 · 4강에서 정한 최신 이름 기준)
SUPABASE_URL=https://abcdefgh.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxx
SUPABASE_SECRET_KEY=sb_secret_xxxxxxxxxxxxxxxx
SUPABASE_JWKS_URL=https://abcdefgh.supabase.co/auth/v1/.well-known/jwks.json
SUPABASE_DB_URL=postgresql://postgres:비밀번호@db.abcdefgh.supabase.co:5432/postgres

VITE_SUPABASE_URL=https://abcdefgh.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxx

.env.sample(값이 비어 있는 견본)은 GitHub에 올라가 있어도 괜찮고, 오히려 그래야 합니다. 챙겨야 하는 건 값이 채워진 .env입니다.

내용 전체를 복사해 안전한 곳에 붙여넣기

터미널에서 마우스로 드래그해 선택하면 자동으로 복사됩니다(VS Code 기본). 메모 제목은 “my-shop .env (실습서버 백업)” 처럼 프로젝트 이름을 넣어 두세요. 프로젝트가 여러 개면 각각.

키 이름도 함께 기억하기

4강 가이드에서 정리한 키 이름(SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, SUPABASE_SECRET_KEY … 와 VITE_ 두 줄)이 코드에서 그대로 쓰입니다. 나중에 새 환경에서 .env를 만들 때 이름이 한 글자라도 다르면 “저장이 안 된다”는 증상으로 나타납니다. 값만이 아니라 줄 전체를 복사하는 이유입니다.

잃어버렸다면 — Supabase에서 다시 볼 수 있습니다

Supabase 대시보드 → 내 프로젝트 → Project Settings → API(또는 API Keys)에서 URL과 키를 다시 확인할 수 있습니다. 데이터(표)는 Supabase에 그대로 있으니 키만 다시 가져오면 됩니다. 다만 서버에만 적어둔 다른 서비스의 키(결제·메일 등)가 있다면 그 서비스 관리 화면에서 각각 다시 발급받아야 합니다.

반대로 — .env가 GitHub에 올라가 있는 것을 발견했다면

메모해 두는 것보다 키를 새로 발급(교체)하는 것이 우선입니다. 저장소가 비공개(private)여도 원칙은 같습니다. 절차는 문제 해결 → “.env가 GitHub에 올라갔다”에 있습니다.

GitHub 페이지를 새로고침해 .env가 사라졌는지 봅니다. 그리고 다시는 안 올라가도록 .gitignore에 .env 줄이 있는지 확인합니다.

📛 git status에 빨간 파일이 수천 개 나옵니다
증상: Untracked files 아래로 node_modules/… 가 끝없이 나열됨

.gitignore가 없거나 node_modules 줄이 빠진 것입니다. Claude 패널에 “이 프로젝트에 맞는 .gitignore 만들어줘. node_modules와 .env는 꼭 제외해줘”라고 요청한 뒤, git status를 다시 보면 목록이 짧아집니다. 그다음 git add .로 진행하세요.

이미 git add .까지 해버렸다면: git rm -r --cached node_modules 를 실행하고(파일은 남고 목록에서만 빠짐) 다시 커밋합니다.

📁 fatal: not a git repository
증상: git 명령을 쳤더니 저장소가 아니라고 함

둘 중 하나입니다. ① 지금 있는 위치가 프로젝트 폴더가 아님 — pwd로 현재 위치를 확인하고 cd ~/my-shop으로 들어가세요. ② 이 폴더는 Git으로 관리된 적이 없음 — Case B의 네 줄(git init부터)을 따르세요.

🪪 Author identity unknown / Please tell me who you are
증상: 커밋하려는데 이름을 알려달라고 함

Git 이름표가 없는 상태입니다(새 노트북에서 흔합니다). 두 줄만 실행하고 커밋을 다시 하세요.

터미널 · 따옴표 안을 본인 것으로
git config --global user.name "홍길동"
git config --global user.email "me@example.com"
🔌 서버에 접속이 안 됩니다
증상: Could not establish connection / 연결 시도 후 실패

서버가 이미 종료된 뒤라면 안타깝지만 복구할 수 없습니다. GitHub에 올려둔 코드가 있다면 PART 5로 새 작업실에서 이어가세요. .env는 Supabase 대시보드에서 다시 가져올 수 있습니다(PART 4).

서버가 아직 운영 중인데 안 된다면 2강 가이드의 문제 해결(키 권한, config, 와이파이 22번 포트 차단 → 휴대폰 핫스팟)을 먼저 확인하고, 그래도 안 되면 어디까지 했는지 + 화면 캡처 + OUTPUT 패널(Remote - SSH) 내용을 강사에게 보내주세요.

🪟🍎 노트북에서 'npm'은(는) 인식되지 않습니다 / npm: command not found
증상: Node.js를 설치했는데 터미널이 npm을 모름

설치 전에 열어둔 터미널은 새 프로그램을 모릅니다. VS Code를 완전히 종료(창 모두 닫기)했다가 다시 열고 새 터미널에서 node -v를 쳐보세요. 그래도 안 되면 Windows를 재부팅한 뒤Mac에서 터미널 앱을 완전히 종료(Cmd+Q)한 뒤 다시 시도합니다.

🪟 npm.ps1 파일을 로드할 수 없습니다 / running scripts is disabled on this system
증상: Windows에서 npm을 치면 보안 정책 오류

PowerShell의 기본 보안 설정입니다. 한 번만 풀어주면 됩니다.

🪟 PowerShell (VS Code 터미널)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Y를 입력하고 Enter → 터미널을 새로 열고 npm -v. 이 설정은 “내가 설치한 프로그램의 스크립트는 허용”이라는 뜻으로, 일반적인 개발 환경의 표준 설정입니다.

🗄 노트북에서 화면은 뜨는데 저장이 안 되거나 데이터가 안 보입니다
증상: 폼을 제출해도 표에 안 쌓임 / 콘솔에 Invalid API key, undefined 등

십중팔구 .env가 없거나 이름이 다른 것입니다. 프로젝트 폴더 안에 .env가 있는지(숨김 파일 표시), 줄 이름이 4강에서 정한 이름(SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY …)과 정확히 같은지 확인하세요. 고친 뒤에는 개발 서버를 껐다(Ctrl+C) 다시 켜야 반영됩니다 — .env는 시작할 때만 읽습니다.
